# A bundled VRT helper script supplements compose-CLIs

PoC validation (matrix story over 904×510, pixelmatch 7.2.0) showed that the VRT pipeline cannot be a single `npx pixelmatch` call: Figma exports are transparent PNGs that mismatch a white DOM (~88% noise without flatten), Storybook iframes have an 8px `body` margin that becomes a 16px offset at DSF=2, MCP `get_screenshot` cannot return scale=2 (REST `/v1/images?scale=2` is required), and pixelmatch hard-fails on dimension mismatch (which is the default unless playwright runs with a custom viewport equal to the Figma frame and `deviceScaleFactor=2`). We ship `skills/fe-design-check/vrt.mjs` — a ~60-line Node script that wraps `sharp` (flatten + future normalize), `playwright` (custom viewport, DSF=2, font-ready wait), and `pixelmatch` (default options: `threshold: 0.1`, `includeAA: false`) into one CLI. SKILL.md files call it with five flags; the helper emits JSON to stdout and writes `figma.png` / `code.png` / `diff.png` to `.fe-design-cache/diff/`.

## Consequences

- ADR-0001 ("compose existing CLIs, no published npm package") still holds — `vrt.mjs` is not on npm. It lives in the skill repo, versioned alongside the SKILL.md that invokes it, and is installed wherever the skill itself is installed (typically `~/.claude/skills/fe-design-check/`).
- The user's project must install four devDeps (`sharp`, `playwright`, `pixelmatch`, `pngjs`) plus run `npx playwright install chromium` once. SKILL.md precheck flags this.
- The default `vrtThreshold` shifts from `0.001` to `0.05`. Two PoC rounds converged on this: a 904×510 matrix story has a 1.37% baseline (so `0.015` works there), but a single button at DSF=2 (126×56 = 7056 px) carries 5–8% baseline from text-glyph rendering alone (Chromium font fallback vs. Figma renderer). Default `0.05` accommodates small components by default; matrix / page-sized stories can lower `vrtThreshold` in `figma.config.json` to `0.015` for tighter checks. See `fe-design-check/SKILL.md` for the empirical table.
- vrt.mjs resolves its runtime deps (`sharp`, `playwright`, `pixelmatch`, `pngjs`) from `process.cwd()/node_modules` via `createRequire` + dynamic `import`, so the script can run from any location (typically `~/.claude/skills/fe-design-check/`) while finding the user project's installed deps. Install happens in the user project, not the skill directory.
- Sub-1pp regressions (e.g. a 4px padding shift on a small region of a large render) fall below the global ratio cut and are not caught by the verdict alone. The skill mitigates this by emitting per-variant stories (small canvas → bigger relative ratio) and by always reading `diff.png` multimodally in the AI reporting step.
- Trade-off: a small amount of orchestration code lives in the skill rather than fully in prose. Lifting the same logic into AI instructions every invocation would burn tokens and risk drift between runs; bundling it in `vrt.mjs` keeps the behaviour stable. The cost is one Node script to maintain inside the skill repo.
