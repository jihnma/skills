# PR conventions

Detect the repo's own conventions first; fall back to wrapper defaults only when the repo has no clear signal.

## Branch naming

Inspect recent active branches:

```sh
gh api repos/<O>/<R>/branches --paginate -q '.[].name' | head -30
```

Pattern inference (≥ 50% of recent branches matching → "clear convention"):

| Observed pattern | Use |
|---|---|
| `feat/X`, `fix/Y` | `feat/issue-<N>-<slug>` |
| `<KEY>-description` (e.g. `PROJ-456-...`) | `<KEY>-<slug>` (JIRA case) |
| `<username>/topic` | `<gh-user>/issue-<N>` |
| No clear pattern | **Fallback** `design/issue-<N>` (GitHub) or `design/<KEY>` (JIRA) |

If the chosen name collides with an existing branch (not from a prior wrapper run — idempotency handles that): append `-<short-timestamp>`.

## PR title

If `.github/pull_request_template.md` exists with a title placeholder, honor it. Otherwise: `[design] <issue title>` (issue title taken verbatim — don't paraphrase).

## PR body

Template-aware:

1. Check `.github/pull_request_template.md`, `.github/PULL_REQUEST_TEMPLATE.md`, `.github/PULL_REQUEST_TEMPLATE/*.md`. First match wins.
2. If a template exists, use it as the base. Fill any `Closes #` / `Related Issue:` placeholder. If no such placeholder exists, prepend `Closes #<N>` (GitHub) or `Ticket: <URL>` (JIRA) at the top.
3. **Append** wrapper sections after the template content:

```markdown
## Summary
<intent from gate, 2-3 lines>

## Results
<details>
<summary>Button — ✅ 0.4%</summary>

| Figma | Code | Diff |
|---|---|---|
| ![](<blob URL>) | ![](<blob URL>) | ![](<blob URL>) |

</details>
<details>
<summary>Input — ⚠️ 8.2% (Border-radius mismatch)</summary>
...
</details>
```

No "Generated by" footer. No "Follow-up tasks" section — `// TODO` comments in code carry that.

## Commit message style

`git log -20 --pretty=%s` → if ≥ 70% match Conventional Commits (`feat(...):` / `fix(...):` / etc.), use `feat(<component>): implement from #<N>`. Otherwise plain `Implement <Component> from #<N>`.

One commit per component. Squash-merge repos collapse them in the end; reviewer sees per-component diff in the meantime.

## Labels / assignees

- **Labels**: apply `design-implementation` **only if** `gh label list` already contains it. Never auto-create.
- **Assignees**: `gh auth status` user.
- **Reviewers**: never auto-assigned (CODEOWNERS / project rules handle this).

## Draft vs ready

- All VRT pass → `gh pr ready <N>`.
- Any VRT fail → leave as draft.
- Setup error → PR never opened (handled upstream by failure-modes table).
